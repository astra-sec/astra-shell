# UI-18 legacy worker maintenance candidate

Scope: only UID1000 xy; shared production gateway and UID1001 mimi stay unchanged.
This is a maintenance candidate, not yet deployed or accepted.

Baseline cc05c54 is 589f1f0 plus the existing production palette implementation.
All 82 Cargo/build/src/proto/vendor input files match the 2026-08-28 retained
production source snapshot by Git blob hash. Installed, running and retained
production astrad all hash to 4ef88a5c745462e3dc5c32800cd04f2035c0eefb24e563404159edaf651f5f42.
This establishes source/artifact provenance but is not a byte-reproducible rebuild
claim with a new compiler. The original remote working tree is untouched.

Only semantic attachment implementation changes: one serial bounded writer drain,
dirty + 16ms sampling after drain, epoch/generation dedup under the engine lock,
cancellation-safe receive framing, final authoritative State before Exited, and
retention of the receiver after lag. Raw N-1 attachments retain direct writes.
No schema, capability selection, internal hello, worker lifecycle, gateway routing,
terminal parsing/export/validation semantics or resource limits are changed.
The output handoff uses the already reviewed UI-18 20MiB bound, with at most one
regular full-state export pending drain plus a final exit state; it is not an
unbounded history queue or another terminal authority. Public frame limits remain.

Required before deployment: fixed-source Linux build/tests; original production
binary as isolated managed gateway with the candidate as prestarted xy worker;
same rich full-state workload, slow receiving with concurrent input, final state
and control order. No live user terminal is part of this test.

A live single-worker switch must use exact PID/UID/start fencing and fail once if
the existing gateway races to start another worker. Never remove a live socket or
kill a winner in a loop. Because the unchanged gateway starts its own binary,
this candidate is a **temporary current-worker repair**: on idle timeout/crash,
the gateway can launch the old version. No persistent per-UID version routing is
implemented or claimed; WORK-03 remains unfinished. Retain the original binary,
state metadata/permissions and an explicit single-worker rollback recipe.
